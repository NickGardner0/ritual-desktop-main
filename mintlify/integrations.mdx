Ritual connects to wearables and devices via OAuth and native APIs. Below is a tabular breakdown of each integration’s endpoints and what is tracked automatically.

---

## Whoop

Whoop uses OAuth 2.0. Ritual stores tokens encrypted (AES) and polls the Whoop API in the background.

### OAuth 2.0

| Step | Endpoint / action |
|------|-------------------|
| Authorization | User is sent to `https://api.prod.whoop.com/oauth/oauth2/auth` with `client_id`, `redirect_uri`, `scope`, `state` |
| Token exchange | `POST https://api.prod.whoop.com/oauth/oauth2/token` with `grant_type=authorization_code`, `code`, `client_id`, `client_secret`, `redirect_uri` |
| Token refresh | Same token URL with `grant_type=refresh_token` and `refresh_token` |
| Connect in Ritual | Dashboard → Settings → Integrations → Connect Whoop → Authorize |

### Whoop API endpoints (Ritual uses)

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/developer/v1/user/profile/basic` | User profile (after OAuth) |
| GET | `/developer/v1/recovery` | Recovery scores (query: `start`, `end`, `limit`, `nextToken`) |
| GET | `/developer/v1/cycle` | Daily cycles (query: `start`, `end`, `limit`, `nextToken`) |
| GET | `/developer/v2/cycle/{cycleId}/sleep` | Sleep for a given cycle |
| GET | `/developer/v1/activity/workout` | Workouts (query: `start`, `end`, `limit`, `nextToken`) |

### Automatically tracked (Whoop → habits)

| Whoop data | Maps to habit | Unit |
|------------|----------------|------|
| Sleep (REM + slow wave + light, excl. awake) | Sleep duration / sleep | hours |
| Recovery score | Recovery score / recovery | % (0–100) |
| Daily strain (from workouts) | Daily strain / strain | strain score |

## Apple Watch (HealthKit via iOS Companion)

The Ritual iOS companion app reads HealthKit and sends normalized metrics to the Ritual backend. Sign in with the same account and grant HealthKit permissions.

### HealthKit metrics Ritual can track

| Metric type | Description | Unit |
|-------------|-------------|------|
| steps | Step count | count |
| active_energy | Active energy burned | kcal |
| basal_energy | Basal energy burned | kcal |
| distance | Walking/running distance | meters / km / miles |
| flights_climbed | Flights climbed | count |
| exercise_time | Exercise minutes | minutes |
| stand_time | Stand hours | hours |
| hr | Heart rate | bpm |
| hrv | Heart rate variability | ms |
| resting_hr | Resting heart rate | bpm |
| walking_hr | Walking heart rate | bpm |
| respiratory_rate | Respiratory rate | breaths_per_minute |
| oxygen_saturation | SpO2 | percent |
| sleep_session | Sleep session (in bed) | minutes |
| sleep_asleep | Time asleep | minutes |
| sleep_awake | Time awake in bed | minutes |
| sleep_rem | REM sleep | minutes |
| sleep_deep | Deep sleep | minutes |
| sleep_core | Core sleep | minutes |
| workout | Workout sessions | — |
| mindful_minutes | Mindfulness minutes | minutes |

Data is sent to the backend via the ingest API (device registration, HMAC-signed requests, optional incremental sync with HealthKit anchors).

## Oura Ring

Oura uses OAuth 2.0. The following is the standard API surface; Ritual’s Oura integration may be in development.

### OAuth 2.0

| Step | Endpoint / action |
|------|-------------------|
| Authorization | User is sent to `https://cloud.ouraring.com/oauth/authorize` with `client_id`, `redirect_uri`, `scope`, `state` |
| Token exchange | `POST https://api.ouraring.com/oauth/token` with authorization code |
| Requests | `Authorization: Bearer <access_token>` on all API calls |

### Oura API v2 endpoints (usercollection)

| Endpoint | Description |
|----------|-------------|
| `GET /v2/usercollection/personal_info` | Demographics, height, weight (scope: `personal`) |
| `GET /v2/usercollection/daily_sleep` | Sleep scores, stages, duration, quality (scope: `daily` or sleep) |
| `GET /v2/usercollection/daily_activity` | Steps, calories, activity score (scope: `daily`) |
| `GET /v2/usercollection/daily_readiness` | Readiness score, HRV, RHR, recovery (scope: `daily`) |
| `GET /v2/usercollection/heartrate` | Time-series heart rate, e.g. Gen 3 (scope: `heartrate`) |
| `GET /v2/usercollection/spo2` | Daily SpO2 average during sleep (scope: `spo2`) |

Scopes: `daily` (sleep, activity, readiness), `personal`, `heartrate`, `spo2`. HRV and readiness are available via daily summaries.

## Ritual Watcher

The Ritual Watcher is a background process that runs when the desktop app is open. It writes to a local SQLite database; rollups can be synced to the cloud if enabled.

### Automatically tracked (Ritual Watcher)

| Data | Description |
|------|-------------|
| App usage | Active app (bundle ID, app name) and duration per segment; rolls up into daily Computer Use habit |
| Window title | Current window title (optional; privacy modes: off, full, truncate, hash) |
| Browser domains / URLs | Domains (and optionally URLs) from the active browser tab; from native watcher and/or browser extension heartbeat |
| Browser tab changes | Tab/URL changes when a supported browser is in focus (polling) |
| AFK | Away-from-keyboard detection so idle time does not count as active computer time |
| Screen lock / unlock | Lock and unlock events for session boundaries |
| Sleep / wake | System sleep and wake for session boundaries |
| Session timing | Start/end timestamps per activity segment and daily rollups (active_ms, event count) |

Exclusions (apps or domains not tracked) can be set in Settings → Computer Tracking → Exclusions. Computer tracking data is stored locally first and only synced to the cloud (e.g. Tinybird) if cloud sync is enabled.

## Weather

Weather context (e.g. temperature and conditions) is attached to log entries by location. No separate setup; it is applied automatically where supported.
