---
title: "Integrations"
description: "Devices and data sources that connect to Ritual automatically."
---

Ritual works best when manual tracking and passive sources are combined. Passive integrations reduce friction — you don't have to remember to log what your devices already know.

## Live Integrations

These are available now in the current version of Ritual.

| Source | Type | Notes |
|--------|------|-------|
| Ritual Desktop Watcher | Desktop | Computer Time, active apps, websites, and local activity fallback |
| Apple Biome / iPhone Time | Device usage | iPhone foreground app usage when local Biome sync data is available |
| Location Context | Context | Optional location pings can enrich habit and activity logs |
| Apple Watch / Health | Wearable | Activity, heart rate, sleep, steps, workouts, and related health signals through supported import/sync paths |
| Whoop | Wearable | Sleep, recovery, strain, and workout data |
| Oura Ring | Wearable | Sleep, readiness, activity, and recovery signals where configured |
| Garmin | Wearable | Activity, workouts, and health metrics where configured |
| Plaid | Finance | Spending context for finance-related habits and summaries |
| Weather | Context | Daily weather context for richer review and summaries |

<Info>
  iPhone Time depends on Apple Biome data being available on a Mac account that can read the synced App.InFocus stream. Some setups may require additional local setup or export/import bridging.
</Info>

## In Development

These areas are still being expanded and refined.

| Source | Type | Notes |
|--------|------|-------|
| Google Calendar | Schedule | Calendar context for daily summaries and planning |
| Additional phone usage sources | Device usage | Backup paths for Screen Time when Biome data is unavailable |
| More wearable providers | Wearable | Broader provider coverage and more granular health signals |
| Import workflows | Data import | CSV and screenshot-based import cleanup for historical data |

## Philosophy

Ritual treats integrations as context layers, not scorecards. The goal is to give you a richer picture of why your habits went the way they did, not to add more things to optimize.
